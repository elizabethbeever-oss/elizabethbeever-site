# Elizabeth Beever | Professional website

[Visit the live website](https://elizabethbeever.com)

A personal website bringing together my writing, selected work and developing interests in digital health, responsible AI, healthcare innovation, digital clinical safety and product development.

## Why I built it

I wanted a straightforward place to share published writing and practical work, and an opportunity to learn more about building, deploying and evaluating a digital product.

The website is also an ongoing exercise in using AI-assisted development tools thoughtfully: defining what I need, reviewing generated work, testing the result and making improvements based on evidence.

## What I worked on

- **Content and product decisions:** defining the intended audience, information structure and professional positioning.
- **AI-assisted development:** using AI tools to support implementation and iteration, while reviewing and deciding which changes to make.
- **Delivery:** managing website files and changes through GitHub, with a live custom-domain deployment.
- **Search visibility:** setting up metadata, a sitemap and Google Search Console, and checking indexing and technical SEO.
- **Evaluation:** testing the homepage and article on mobile and desktop using Lighthouse, then revisiting accessibility findings.

## Technology and approach

The site uses HTML and CSS with responsive layouts and light/dark colour schemes. GitHub is used for version control and change review. Google Search Console and Lighthouse support ongoing evaluation.

This is a learning and portfolio project, not a production healthcare application.

## Testing and limitations

In November 2026, Lighthouse returned performance scores of **100/100** on mobile and desktop for the homepage and first article. Automated accessibility scores were **94/100** and **92/100**, respectively, with further checks needed.

These are point-in-time automated test results. They do **not** establish WCAG 2.2 AA conformance or guarantee performance on every device. Manual keyboard, screen-reader, zoom and narrow-viewport testing remain important.

## What I've learnt

AI-assisted development can make it easier to get a working first version, but a plausible result still needs checking. This project has helped me practise making requirements explicit, reviewing technical outputs, using test results to guide changes and recognising where an automated score has limits.
